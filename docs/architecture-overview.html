HR Workflow Designer

Architectural overview, technical stack decisions, and foundational concepts for the visual workflow orchestrator.

Technology Stack

React ^19.2.5

Frontend framework. Used for fast HMR and highly optimized component rendering.

Vite ^8.0.9

Build tool and dev server. Provides instant server start and lightning-fast HMR.

Zustand ^5.0.12

State Management. A centralized, unopinionated, and highly performant state container.

React Flow ^12.10.2

Canvas Engine. Provides the robust interactive node-based UI mapping and edge connections.

Dagre ^0.8.5

Algorithmic Layout. Mathematical calculation engine for automatic non-overlapping node positioning.

Styling. Utility-first CSS framework for rapid and consistent UI styling across components.

MSW ^2.13.4

Network API Layer. Mock Service Worker intercepts requests to simulate a fully decoupled backend.

TypeScript ~6.0.2

Type System. Strict discriminated unions ensure payload integrity and robust development.

Core Architectural Decisions

State Management

Zustand vs. Context

How it works

The entire graph state (nodes, edges), validation results, history stack, and UI states are lifted into a single Zustand store.

Why we did it

Predictability & Performance: It acts as a single source of truth and completely avoids the massive re-rendering overhead common with React Context when deeply nested components access state. This ensures the canvas, validation engine, and configuration sidebar remain perfectly synchronized.

History & Undo/Redo

Native Memento Pattern

How it works

The store contains `past` and `future` arrays. Before any state mutation, a complete snapshot of the nodes and edges is pushed to the `past` array natively.

Why we did it

Lightweight Control: Avoids the bloat of relying on heavy third-party history libraries. It gives us fine-grained control over what constitutes an "undoable" action right at the state mutation level.

Workflow Validation

Reactive Real-Time Engine

How it works

The `validateWorkflow` function runs reactively whenever the graph changes. It checks for disconnected graphs, missing required data, and orphan nodes.

Why we did it

Immediate Feedback: Users receive instant visual feedback (kinetic pulsing on nodes) if their workflow is invalid. Errors only clear the exact millisecond the root cause is fixed in the data model.

Node Configuration

Unified Inspector Panel

How it works

Rather than building separate, complex inline editors for each node type, all data mutations are routed through a single slide-out Inspector Panel.

Why we did it

Professional UX: Keeps the canvas visual representation clean and uncluttered. It mimics professional IDEs providing a consistent place for users to configure properties and validations.

Backend Integration

Network-Level Simulation via MSW

How it works

MSW intercepts `POST /simulate` and `GET /automations` requests, processes the actual JSON payload, and returns mock execution logs.

Why we did it

Zero-Friction Migration: Simulates a real backend without littering the frontend code with mock data logic. When a real backend is built, the frontend requires absolutely zero changes; we simply turn off the MSW worker.

Frequently Asked Questions

Why aren't we using React Context for the canvas state?

React Context causes significant re-rendering issues when deeply nested components (like hundreds of nodes on a canvas) listen to complex state changes. By using Zustand, we selectively subscribe to state slices, meaning an update to Node A does not cause Node B to re-render, keeping our canvas performant at 60 FPS.

How is the auto-layout mathematically calculated?

We utilize Dagre, a library for directed graph layout. Dagre processes the nodes and edges purely as data objects to calculate a non-overlapping, hierarchical tree structure. Once the coordinates are calculated, they are pushed to the React Flow node state to visually update the UI.

How is Type Safety enforced for different node types?

In our type definitions, WorkflowNodeData is established as a Discriminated Union. This means TypeScript strictly enforces that a "Task Node" must have an "assignee" field, while an "Approval Node" must have a "role" field. This eliminates a vast majority of runtime data shape errors.

What is required to scale this to an Enterprise Production environment?

Scaling requires replacing MSW with a real execution engine (like Temporal.io), adding database persistence (PostgreSQL/Redis) instead of localStorage, implementing Canvas Viewport Virtualization to handle workflows with thousands of nodes, and potentially adding CRDTs (like Yjs) for real-time multiplayer collaboration.
